# Feature Specification: 远程可达的个人 Agent

**Feature Branch**: `001-remote-agent-access`

**Created**: 2026-11-03

**Status**: Draft

**Input**: 用户描述：「让跑在 NAS 上的个人 Agent 不再被『必须在家』绑定：从任意设备（Windows 笔记本、iOS/Android 手机）用浏览器打开一个网址就能继续用它，客户端不安装任何东西；它能读写/执行、能续接会话；不买域名、不租服务器。」

## Clarifications

### Session 2026-11-03

- Q: 当 Agent 读到的文件或网页里藏着「忽略之前的指令、去执行某条命令」这类文字时，第一版要做到什么程度？ → A: B —— 系统层声明优先级（工具读到的内容一律视为「资料，非指令」，优先级低于用户指令），并在界面上把这类内容标注为不可信。
- Q: 会话记录（含命令输出、文件片段）会一直累积，第一版按什么策略清理？ → A: A —— 无限期保留，不做自动清理；用户可手动删除指定会话。
- Q: 你会在多台设备上开这个 Agent，凭证按哪种模型设计？ → A: B —— 每设备一个独立令牌，可单独吊销，吊销后立即失效。
- Q: 锁定阈值与窗口要不要写死？ → A: 同意写死 —— 同一来源 15 分钟内 20 次失败即锁定 15 分钟，锁定期间正确凭证也被拒。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 异地用浏览器接着用我的 Agent (Priority: P1)

我坐在公司或咖啡馆，用 Windows 笔记本（或手机）浏览器打开同一个固定网址，打开页面并完成设备认证，看到我昨天的对话；我说「把工作目录里那个草稿整理一下」，Agent 在 NAS 上真的动手改文件，并把结果流式地显示给我。

**Why this priority**: 这是整个 Feature 存在的理由——「人不在家就失去动手能力」。其它能力都建立在「能从外部安全地触发一次对话」之上。

**Independent Test**: 在家庭网络之外的设备上打开入口地址，完成 ≥3 轮对话并触发 1 次产生可验证副作用的操作（文件内容变化或命令输出与真实状态一致）。

**Acceptance Scenarios**:

1. **Given** 我在家庭网络之外且未通过身份校验，**When** 我访问入口地址，**Then** 我拿不到任何会话内容，且请求被明确拒绝。
2. **Given** 我通过了身份校验，**When** 我提交一句话，**Then** 我在 5 秒内看到回复开始逐字出现（而非整段等待）。
3. **Given** 我要求「看看工作目录里有什么」，**When** Agent 执行完，**Then** 回复中的目录内容与工作目录的真实状态一致。
4. **Given** 一次任务正在执行，**When** 我点击中断，**Then** 执行停止、界面显示「已中断」，且我可以继续下一轮对话。

---

### User Story 2 - 会话不因服务重启而丢失 (Priority: P2)

晚上回家更新了服务端配置并重启，第二天在外地打开页面，昨天的对话还在，我可以接着追问「刚才那个文件你改到哪一步了」。

**Why this priority**: 没有持久化，这个 Agent 就只是「一次性的网页终端」，长期价值为零；这是把它当长期工具而非临时实验的分水岭。

**Independent Test**: 连续对话若干轮后重启服务端，再次连接能读到历史并基于历史回答。

**Acceptance Scenarios**:

1. **Given** 我与 Agent 已有 ≥3 轮对话，**When** 服务端重启后我重新连接，**Then** 历史消息完整可见。
2. **Given** 历史已恢复，**When** 我问「上一轮你读到的那段内容是什么」，**Then** Agent 基于历史回答，不需要重新读取文件。

---

### User Story 3 - 单个活跃会话，跨设备一致 (Priority: P3)

我在笔记本上聊到一半，出门用手机打开同一入口，看到的是同一个会话的当前状态，可以接着聊。

**Why this priority**: 单用户场景下「多设备抢同一个会话」是真实需求，但它不阻塞 MVP；只要状态在服务端而不是浏览器里，这一条自然成立。

**Independent Test**: 用两个不同设备先后连接同一会话，第二个设备能看到第一个设备的对话内容与状态。

**Acceptance Scenarios**:

1. **Given** 我在设备 A 上聊了若干轮，**When** 我用设备 B 打开入口，**Then** 我能看到设备 A 的对话内容。
2. **Given** 设备 A 正在生成回复，**When** 设备 B 打开会话，**Then** 界面明确显示「正在处理中」，而不是给出不一致的空状态。

---

### Edge Cases

- **模型不可用或额度耗尽**：必须在界面上给出可读原因，消息不丢失，可重试。
- **Agent 卡在长任务**：超过预期时长时有超时提示，用户可以中断。
- **同时发起两次请求**：第二个请求要么排队，要么被明确拒绝；不得两个执行流交叉写同一会话。
- **会话记录损坏或不可读**：回退为新会话并明确告知，而不是静默从零开始。
- **公网入口不可达**：给出「入口不可达」与「鉴权失败」的区分，避免用户误判为凭证失效。
- **工作目录被写坏**：用户可看到每次修改了哪些文件，以便自行回滚。
- **不可信内容注入**：Agent 读到的文件或网页内容可能包含指令性文字。这类内容一律按「资料」对待——不改变用户的既有授权，也不得被当作新指令执行；界面需明确标注其来源与不可信属性（见 FR-015）。
- **存储空间耗尽**：明确报错并停止写入，不得静默丢弃历史或写入截断的会话（见 FR-017）。
- **设备丢失**：吊销该设备凭证后，它的下一次请求即被拒绝，其他设备不受影响（见 FR-018）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 提供单一公开入口，客户端只需要浏览器；不得要求用户在被访问设备上安装 VPN、组网或隧道客户端。
- **FR-002**: 系统 MUST 对每一次交互请求做身份校验，校验失败一律拒绝；拒绝响应不得泄露会话存在性、内容或内部错误细节。凭证 MUST 按设备独立签发，可单独吊销。
- **FR-003**: 用户 MUST 能够进行多轮对话，且回复以流式方式逐字呈现。
- **FR-004**: Agent MUST 能够在指定的工作目录内读取、写入文件并执行命令，并把执行结果返回给用户。
- **FR-005**: 会话 MUST 在服务端持久化；服务端重启后，会话可恢复并继续。
- **FR-006**: 用户 MUST 能够中断正在执行的任务，且中断后会话仍可继续。
- **FR-007**: 系统 MUST 限制请求频率：正常请求每设备每分钟 ≤ 60 次、每来源每分钟 ≤ 120 次；认证失败按来源 IP 累计（失败请求没有可信的设备身份），**同一来源 IP 在 15 分钟窗口内失败 ≥ 20 次即锁定 15 分钟**，锁定期间即使凭证正确也拒绝。
- **FR-008**: 系统 MUST 记录审计事件：何时、由谁（凭证标识）、执行了哪类动作、结果如何；审计记录不得包含完整凭证。
- **FR-009**: Agent 可访问的文件范围 MUST 限定在工作目录与会话数据目录内；宿主机的个人配置与凭据 MUST NOT 对其可见。
- **FR-010**: 当外部模型服务不可用、超时或被限流时，系统 MUST 返回可读错误并保留用户消息，允许重试。
- **FR-011**: 客户端界面 MUST 在桌面浏览器与手机浏览器上都能完成完整对话（输入、流式查看、中断）。
- **FR-012**: 执行命令与写入文件的能力 MUST 默认开启，与 Agent 原生默认保持一致；相应的风险 MUST 由隔离边界（FR-009）、身份校验（FR-002）、限流（FR-007）与审计（FR-008）共同承担。
- **FR-013**: 本期 MUST 只维护单个活跃会话；同一时刻只接受一个执行流，第二个请求排队或被明确拒绝（见 Edge Cases）。
- **FR-014**: 界面上 MUST 展示每一次实际动作（读取 / 写入 / 执行）的对象与结果摘要，使用户能察觉并纠正误操作。
- **FR-015**: Agent 通过工具读到的内容（文件、命令输出、网页）MUST 被视为**资料而非指令**：系统中 MUST 声明其优先级低于用户指令；界面 MUST 以可区分的方式标注这类内容的来源与不可信属性。
- **FR-016**: 会话与动作记录 MUST 无限期保留，系统 MUST NOT 自动删除或归档历史；用户 MUST 能主动删除指定会话。
- **FR-017**: 当存储空间不足时，系统 MUST 明确报错并停止写入，MUST NOT 静默丢弃历史或产生截断的会话。受影响范围包括：会话记录写入、审计事件写入；凭证签发与吊销失败时同样必须显式报错，不得假成功。
- **FR-018**: 每个设备 MUST 使用独立的凭证，并带有可识别的设备标签与最近使用时间；吊销某个凭证后，该设备的**下一次请求**即被拒绝，且不影响其他设备，无需重启服务。
- **FR-019**: 用户 MUST 能查看当前有效的设备凭证清单（标签、创建时间、最近使用时间），并逐条吊销。
- **FR-020**: 当浏览器不支持读取流式响应、或流式连接在生成过程中中断时，客户端 MUST 自动降级到非流式路径（整段返回或短轮询），使用户仍能完成同一轮对话；降级发生时 MUST 在界面上明确告知当前处于降级模式。

### Key Entities *(include if feature involves data)*

- **会话（Session）**：一次持续的对话上下文，包含标识、创建时间、消息序列、当前状态（空闲 / 处理中 / 已中断）。
- **消息（Message）**：用户或 Agent 的一次发言，包含角色、内容、时间戳；Agent 消息可关联工具调用记录。
- **工具调用记录（Action Record）**：一次实际动作（读取、写入、执行）的参数摘要与结果摘要，用于向用户展示「它到底做了什么」。
- **访问凭证（Credential）**：按设备签发的身份凭据，包含设备标签、创建时间、最近使用时间、状态（有效 / 已吊销）；吊销后立即失效。
- **审计事件（Audit Event）**：时间、凭证标识、动作类型、结果。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在家庭网络之外的设备上，从提交问题到看到回复首字，P50 < 5 秒、P95 < 8 秒。
- **SC-002**: 未携带有效凭证的访问成功率为 0%（全部被拒绝），且响应中不出现任何会话内容。
- **SC-003**: 服务端重启后，已有会话的恢复成功率为 100%。
- **SC-004**: 一次真实动作（文件改动或命令执行）产生可验证副作用的成功率为 100%——即用户看到的「已修改 / 已执行」与实际磁盘和进程状态一致。
- **SC-005**: 同一来源 IP 在 15 分钟窗口内连续 20 次鉴权失败后，第 21 次请求被拒绝（`429`），且锁定持续 15 分钟——锁定期间即使凭证正确也被拒绝。
- **SC-006**: 在 390×844 与 360×640 两种移动视口下：页面无横向滚动；输入框与中断按钮的点击区域 ≥ 44×44；回复以增量方式出现。在不支持流式读取的浏览器上，降级路径能完成同一轮对话。证据来自 WebKit 与 Chromium 的移动端模拟；真机不在本期验收范围内（见 Assumptions）。
- **SC-007**: 用户在一次会话中能看清 agent 每次动作的对象与结果，误操作可被察觉并纠正。
- **SC-008**: 吊销一个设备凭证后，该设备的下一次请求被拒绝的比例为 100%，且其他设备在同一时段内的请求成功率不受影响。

## Assumptions

- **单用户**：只有一个人（项目所有者）使用，不涉及账号体系、角色与多租户。
- **单活跃会话**：本期一个时间点只有一个会话、一个执行流；会话切换与并行项目在后续迭代再考虑。
- **能力默认开启**：执行与写入不做二次确认，用户接受「能触发即能执行」的模型，风险由隔离边界与访问控制承担。
- **凭证形态**：每台设备一个独立令牌（可单独吊销），不使用 OAuth 或第三方登录；令牌由用户在服务端签发与吊销。
- **模型来源**：外部模型服务通过标准协议提供，额度与费用由用户承担；不可用时的表现按 FR-010 处理。
- **入口形态**：公网入口由服务端侧的隧道/反代提供（不购买域名），入口地址由服务端决定；该入口**长期开启**，属产品正常运行状态而非临时测试。
- **外部验证手段**：跨地域的外部可达性由一次性的 CI runner 完成验证（不引入第三方托管服务），验证入口地址只作为运行时输入、不写入仓库。
- **执行环境**：Agent 运行在与宿主机隔离的执行环境中，工作目录为挂载卷。
- **访问设备**：用户使用现代浏览器（Edge / Chrome / Safari 近两年版本），不要求安装插件。
- **移动端验收不含真机**：项目所有者没有 iPhone，也无法执行真机手工测试。因此移动端以 WebKit 与 Chromium 的移动视口模拟作为验收证据，并通过 FR-020 的降级路径降低「真实 iOS Safari 行为与模拟不一致」的风险。真机行为列为已知未验证项，不写成已通过。
- **网络条件**：跨境链路延迟存在，1–3 秒的往返开销已在指标中体现，不追求本地终端级手感。
- **数据范围**：会话与工作文件属于个人数据，不上传第三方；本期不做多副本与异地备份。
- **Basecamp 依赖**：Agent 能力集由既有 agent 框架提供（见项目宪法原则 I），本 Feature 不新增 Agent 能力，只解决「可达、安全、可续」。
